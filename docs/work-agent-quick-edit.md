# Быстрые правки Work вместе с владельцем

Для изменения видимых карточек не читай весь учебный корпус и не редактируй
исходники приложения. Начни с короткого текущего контекста того же хранилища:

```powershell
mmm work edit context
```

Контекст содержит revision, выбранную карточку/задачу/событие, текущий день и
короткий список предложений. Для более широкого списка передай `--limit 20`.
Установленный `mmm` использует выбранные данные Brainalot. При запуске
исходников или из отдельного worktree явно передавай `--root` действующего
хранилища из конфигурации/контекстного комплекта, чтобы не создать второе.
Если карточка не выбрана, используй её стабильный ID из списка, не подбирай
по похожему названию. Контекст и данные всегда перечитывай после конфликта.

Обычная правка — одна текстовая команда. Подставь фактические ID и revision:

```powershell
mmm work edit rename 'Подготовить урок' --id CUBE_ID --revision 105 --request-id voice-rename-1
mmm work edit place 2026-10-26 19:00 --id CUBE_ID --revision 106 --request-id voice-place-1
mmm work edit duration 30 --id CUBE_ID --revision 107 --request-id voice-duration-1
mmm work edit period 2026-11-09 2026-11-15 --id TASK_ID --revision 108 --request-id voice-period-1
```

`place` без времени выбирает день без назначения часа. Также есть `return`,
`delete`, `goal`; `rename --kind task|event|assignment|goal` меняет соответствующий
элемент. `period` — покрытие рабочей задачи днями, не переписывание исходного
дедлайна курса. Короткие команды возвращают только результат/новую revision.
Для повтора после неопределённого ответа используй те же ID, аргументы,
`--revision` и `--request-id`. Не заменяй конфликт новой ревизией вслепую.

Остальные возможности доступны теми же короткими типизированными операциями
через `work period command --file <UTF-8.json>`, без переписывания UI/SQLite
или полного документа Work. Пример формы:

```json
{"request_id":"voice-rename-1","expected_revision":105,"action":"cube_rename","data":{"cube_id":"CUBE_ID","title":"Подготовить урок"}}
```

Native-сведения/факты и содержимое обычных карточек редактируются через
`work plan command --file <UTF-8.json>`; этот CLI использует тот же координатор,
что День. Не применять импорт/restore/replan для простой правки названия/времени.
Календарные переносы/оценки в Work локальные и не меняют Google Calendar.
Не выдумывать готовность по затраченному времени. Существующие факты и
обязательные события защищены; ошибка сохраняет текущие данные и черновик.

Оба режима получают изменения без перезагрузки. В Дне источник выбранного
контекста — открытая карточка, в Неделе — выбранная карточка/задача. Этот режим
позволяет лёгкому форку работать с коротким контекстом вместо всей переписки.
